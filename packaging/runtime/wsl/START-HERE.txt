AgentFEM Complete Runtime for Windows (WSL2 Preview)
===================================================

Runtime version: @VERSION@

1. Extract the entire ZIP file. Do not run the installer from inside the ZIP.
2. Open PowerShell in this extracted folder.
3. Run:

   powershell -ExecutionPolicy Bypass -File .\Install-AgentFEM.ps1

The installer prepares or updates WSL when needed, verifies the bundled image,
creates an AgentFEM WSL2 distribution, and opens its first-time setup. Windows
may show one administrator approval prompt. If it asks for a restart, restart
Windows and run the exact same installer command again. Choose a Linux username
and password when prompted. Password characters are intentionally not displayed.

When setup finishes, run:

   agentfem doctor
   agentfem workspace

By default, projects and results are stored in the Windows Documents folder:

   Documents\AgentFEMProjects

Inside WSL the same directory appears as `~/AgentFEMProjects`. Removing or
replacing the AgentFEM WSL distribution does not remove this Windows folder.

Later, start AgentFEM from the Start menu or run this in PowerShell:

   wsl -d AgentFEM

How AgentFEM prepares WSL
-------------------------

Do not begin with bare `wsl --install`: that command also downloads Ubuntu,
which the AgentFEM Complete Runtime does not need. The bundled installer uses
Microsoft's supported no-distribution route and tries the direct web source,
then the Microsoft Store source if the first command fails.

To require one source explicitly, use one of:

   powershell -ExecutionPolicy Bypass -File .\Install-AgentFEM.ps1 -WslBootstrapSource Web
   powershell -ExecutionPolicy Bypass -File .\Install-AgentFEM.ps1 -WslBootstrapSource Store

Windows may need internet access once to install the WSL platform. The
AgentFEM Linux runtime itself is installed from this offline package; no Ubuntu
distribution is downloaded.

If WSL installation stops making progress
-----------------------------------------

Do not unregister any existing Linux distribution. Open Administrator
PowerShell and inspect the installation first:

   wsl --status
   wsl --version

If Windows has a pending restart, restart the computer and run the AgentFEM
installer again. If the direct web route is slow or unavailable, stop it and
rerun the installer with `-WslBootstrapSource Store`; if the Store route is
unavailable, use `-WslBootstrapSource Web`.

For an x64 machine that must bootstrap WSL offline, install Microsoft's current
x64 WSL MSI from its official release page. Then open Administrator PowerShell,
enable the required Windows virtualization component, and restart:

   https://github.com/microsoft/WSL/releases/latest

   dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

After restarting, rerun:

   powershell -ExecutionPolicy Bypass -File .\Install-AgentFEM.ps1 -WslBootstrapSource None

If WSL is installed but out of date, its equivalent direct command is:

   wsl --update --web-download

If the optional Windows feature was not completed, its equivalent direct
command is:

   wsl --install --no-distribution --web-download

Error `0x80370102` means the Virtual Machine Platform or firmware virtualization
is unavailable. Enable CPU virtualization in the PC firmware/BIOS, confirm the
Windows Virtual Machine Platform feature, restart, and rerun the installer.

Installing a newer AgentFEM runtime
-----------------------------------

Choose one of two explicit upgrade policies.

Safest preview (default): run the newer installer normally. If AgentFEM
already exists, the new runtime is installed beside it as AgentFEM-@VERSION@.
The old runtime and its projects are untouched. Start the candidate with:

   wsl -d AgentFEM-@VERSION@

Replacement upgrade: let the installer validate the new image, back up the
complete old distribution and user home, restore the projects into the new
runtime, and run the health check before finishing:

   powershell -ExecutionPolicy Bypass -File .\Install-AgentFEM.ps1 -Upgrade

The stable launch command remains `wsl -d AgentFEM`. The recovery backup is
kept under LocalAppData by default and its exact path is printed. Delete it
only after opening important projects and checking the new runtime. Advanced
users who explicitly do not want a retained recovery copy may add
`-RemoveBackupAfterSuccess`.

Replacement is transactional rather than a blind overwrite. WSL has no safe
in-place distribution replacement: the installer first validates a temporary
candidate, exports the old runtime, then switches. If a later step fails it
re-imports the old snapshot. Never interrupt Windows while the script says it
is switching or restoring a distribution.

Removing AgentFEM safely
------------------------

Do not use `wsl --unregister AgentFEM` directly. It permanently deletes every
file still stored inside that distribution. Use the bundled safety wrapper:

   powershell -ExecutionPolicy Bypass -File .\Remove-AgentFEM.ps1

It first verifies that the project workspace is on the Windows drive, exports
a recovery snapshot of the runtime, and only then removes the distribution.
The persistent `Documents\AgentFEMProjects` folder is never removed.

Existing WSL or Mamba installations
-----------------------------------

The same storage contract works when AgentFEM was installed with Mamba inside
Ubuntu or another WSL distribution:

   agentfem workspace --protect

This copies and verifies existing `~/AgentFEMProjects` data before linking the
familiar Linux path to the durable Windows Documents folder.

For an AI agent
---------------

Follow this file as the installation contract. Use the default side-by-side
route unless the user explicitly asks for `-Upgrade`; that switch authorizes
the installer-managed backup and replacement transaction only. Do not run
`wsl --unregister` yourself. Before every upgrade or removal, require
`agentfem workspace --json` to report
`protected_from_distribution_removal: true`. After installation, report the
distribution name, AgentFEM version, health-check result, persistent project
directory, and retained backup path, if any. Never replace the bundled WSL
bootstrap with bare `wsl --install`, because that downloads an unrelated default
Linux distribution.
