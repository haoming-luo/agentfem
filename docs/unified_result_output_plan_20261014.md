# AgentFEM 统一结果输出：设计与行动方案

日期：2026-10-14。分支：`feat/unified-result-output`。
基线：`36f4c1b0`（已合入几何弹性工作）。本文是设计方案，不代表新 API 已实现。

## 1. 目标与架构判断

让普通 Step 和自定义有限元问题都能以同一套结果语义，交付可打开、可分析、文件齐全的结果。保留 Study 描述物理、Material 描述材料、Procedure 组织求解、SimulationResult 组织结果的分工。输出层只消费已接受状态，不接管求解、不重写物理场。

本轮复用现有写出器，收束调用方式。普通用户继续使用 `model.step(...).solve_result(output=...)`；自定义方程只补一个公共输出会话入口。现有接口继续兼容，底层写出器移入专家使用说明，不立即删除或改名。

产品默认：保存 XDMF/HDF5 场数据，按需生成 PVD/VTU 展示副本。原始积分点状态与重启动文件保留各自契约。格式不决定科学性，记录保存了什么、转换了什么、遗漏了什么更重要。

## 2. 已核实的现状

- `results/output.py::UnifiedXDMFTimeSeries` 已支持串行单时间步单网格布局；明确拒绝 MPI。不能直接用它替换并行路径。
- `write_result_fields` 已按串行/并行分流；并行路径写 XDMF 并附带 PVD。它处理当前活场，不等于完整历史导出。
- `attach_result_field_output` 已登记文件、记录转换，并保留积分点独立输出；应复用而非重新建立登记规则。
- `FieldOutput.write` 已支持 xdmf/pvd/both，但预先收集全部快照及恢复场；长时间序列需要流式处理。
- `RunContext.publish` 写清单和完成状态，但没有检查已声明输出是否真正齐全。
- `ResultFieldArtifacts.summary` 目前根据是否有 PVD 推断 XDMF 布局；新增串行双输出后会失真，须使布局与后端显式独立。
- 部分通用输出入口将向量主场默认称为 U/Displacement。自定义速度、通量、模态必须显式区分，不能靠向量维数猜测物理意义。

定位文件：`src/agentfem/results/output.py`、`results/core.py`、`results/integration_points.py`、`io.py`、`project.py`，以及各 Procedure 的已接受状态输出连接点。

## 3. 成熟方案的借鉴与取舍

### DOLFINx：按空间与并行能力选择后端

官方文档区分 XDMF、VTK、VTX 能力；VTX 面向高阶/不连续 Lagrange 场，但同一写出器内的函数有空间兼容约束。结论不是全面切换 VTX，而是输出前检查场类型、几何阶次及后端能力，明确插值和恢复过程。

本轮保留当前 XDMF/PVD 后端，不引入 ADIOS2/VTX 依赖。P2 位移与 DG0 应力的组合必须以实际读回测试确定支持范围；不把“格式支持高阶”解释为所有场可无损混写。

来源：[DOLFINx I/O](https://docs.fenicsproject.org/dolfinx/main/cpp/io.html)；[Python I/O API](https://docs.fenicsproject.org/dolfinx/v0.9.0/python/generated/dolfinx.io.html)。前者为滚动文档，实施时以本仓库运行环境为准。

### MOOSE：一次声明，多后端，各自明确执行时机

MOOSE 将输出做成模块化系统，提供简便入口和详细配置，并分别处理场文件、标量与 checkpoint。借鉴输出声明与执行时机的分离；AgentFEM 的默认工程结果只接收已接受状态，失败迭代如需输出则标为诊断数据。

来源：[MOOSE Output System](https://mooseframework.inl.gov/syntax/Outputs/)。

### PyVista/ParaView：验证真实读取，而非仅验证 XML

PVDReader 支持按时间读取数据集，可用于检查时间序列与字段。将读回与渲染列为展示验收，XML/HDF5 检查只证明结构完整，不声称保证任何 ParaView 版本都不崩溃。

来源：[PyVista PVDReader](https://docs.pyvista.org/api/readers/_autosummary/pyvista.pvdreader)。

## 4. 建议架构

调用链：

`Step 或自定义求解循环 → 已接受帧 → 输出会话 → 现有后端 → 文件清单 → publish`

### 4.1 一个结果语义，两个使用入口

1. 普通 Step 保持现有入口，内部接入共用会话；输出字段、频率复用 FieldOutput，不再增加另一套相同配置。
2. 自定义循环拟增加 `results.output_series(...)`，作为同一会话的公开入口。名称与参数在第一批实现时核定。这是生命周期协调器，不是新的格式写出器。

示意（尚未实现）：

```python
with results.output_series(result, path="fields.xdmf", paraview=True) as series:
    # 在求解器接受当前步、状态提交之后调用；不在 Newton 试迭代中调用。
    series.write_accepted(coordinate=t, primary=u, fields=(stress, energy))
run.publish(result)
```

主场语义来自 SimulationResult 字段记录；自定义字段必须声明语义、位置和必要的单位约定。序列坐标注明是物理时间、载荷因子还是模态编号。不能把同样的数值统一冒充时间。

已有全历史的导出，迭代调用同一会话；只有最终场的 result 只导出当前帧，禁止虚构完整历史。初版不再新增一个平行的 `write_series(result)` 快捷入口。

### 4.2 文件角色与空间语义

沿用现有 artifact 键和相对路径，增量补充统一描述：

- field_data：场数据入口及其 HDF5 等依赖；
- visualization：推荐打开的入口，可指向同一个 XDMF，无须强制重复存储；
- material_state：原始积分点材料状态；
- checkpoint：可重启数据；
- history：曲线、标量与表格。

记录主场名称及语义、点/单元/积分点位置、原空间与输出空间、实际转换方法、参考/变形构形、坐标类型、帧数、起止坐标和并行布局。

参考几何默认保留，位移输出三分量展示表示时记录原物理分量数。已经变形的几何不再次推荐 Warp。不同网格的场不偷偷投影到一起；无法支持的组合给出明确处理建议。

### 4.3 流式写出与并行边界

- 每帧完成写出后释放临时恢复场，内存不随历史帧数线性堆积。
- 序列坐标在一个 segment 内严格递增；续算产生新 segment 并记录衔接，初版不承诺任意原文件追加。
- 检查字段集合、空间与拓扑一致性。初版固定网格/拓扑；换网格开启新 segment，不默默继续旧文件。
- 串行复用 UnifiedXDMFTimeSeries；MPI 复用现有集体 XDMF/VTK 路径，不把全模型 gather 到 rank 0。
- MPI 写出与失败传播须集体参与；主 rank 只负责最终小型清单。若文件仍被打开，不能发布完成标志。
- 以临时文件/未完成标志及最后提交的索引区分完整与中断产物；不宣称多个文件可被操作系统原子提交。
- 科学场输出成功而可选展示失败：保留成功文件，标明部分输出失败，不能吞掉异常或改成全部成功。

### 4.4 发布检查与兼容策略

`publish` 只检查和登记，不触发重算、投影或隐式导出。

| 情形 | 行为 |
|---|---|
| 声明了 XDMF 场输出，文件/依赖缺失 | 输出失败状态；严格模式返回非零退出码 |
| 只交付曲线/材料点结果，没有场输出声明 | 正常发布 |
| 旧脚本有活场但无默认场文件 | 一条可操作提示，不破坏旧工作流 |
| 用户明确只生成展示文件 | 如实标注展示用途，不伪装成默认完整场交付 |
| 可选展示失败 | 保留场数据，报告展示失败；严格行为服从请求 |
| 原始材料状态/重启动未请求 | 不自动补写、不误报缺失 |

已有 `completed_with_output_errors` 等状态优先复用，并核对 run 与 result 的状态一致性。严格请求不能被 `RunContext.publish` 再覆盖成 completed。

## 5. 四个小迭代，逐批可交付

### Sprint 1：理清语义与兼容边界（3项）

1. 核对 FieldOutput、ResultFieldArtifacts、attach_result_field_output，建立共享文件角色与布局描述。
2. 修正由 PVD 存在与否推断 XDMF 布局，以及把所有向量默认当位移的问题；保留已知位移和模态命名兼容。
3. 增加静态输出回归：位移、温度、普通向量、模态、P2+DG0；比较文件登记及真实读回字段。

交付：现有接口行为更准确，不要求用户改脚本。

### Sprint 2：统一流式会话（4项）

1. 实现会话的打开、写接受帧、结束、失败状态；复用现有写出器。
2. 将普通 Step 当前输出路径接入，保持原字段与时间序列数值一致。
3. 接入自定义求解循环；处理 cutback、续算 segment、字段与网格变化。
4. 串行与两进程验证；检查写出失败集体传播、无死锁及原始场不被修改。

交付：一份请求生成默认场数据及可选 PVD；内存按当前帧占用，不缓存整个历史。

### Sprint 3：完整交付检查（3项）

1. 检查文件存在、XDMF/PVD 引用、HDF5 数据集/维度、帧数与坐标；不以解析成功冒充物理正确。
2. 将检查连接到 publish，保留现有严格/宽松策略及非零退出约定；测试标量项目豁免。
3. 在标准摘要中输出“推荐打开的文件”“保存的场数据”“缺失项及修复动作”。

交付：用户和 AI 不再靠猜文件名找到展示入口，缺件时有准确诊断。

### Sprint 4：示例、实际读取与文档（4项）

1. 增加标准项目：自定义势能—Newton—已接受步—P2 位移＋DG0 应力/能量—结果发布；案例不自建输出功能。
2. 用 VTK/PyVista 逐帧读回并比较数值；在本机 ParaView 检查打开、时间切换、Warp 和单一几何。
3. 更新 WORKFLOW、AGENT_GUIDE、结果指南、知识卡与 CLI 发现说明；普通用户只呈现两条标准路径。
4. 构建 wheel，在独立安装环境执行示例；运行相关回归与全库检查，区分基线失败。

交付：源码、测试、可运行 project、验证记录、用户说明与审阅分支。

## 6. 必须通过的验收矩阵

- 静态/时间序列，标量/位移/非位移向量，P1/P2 主场＋DG0 场；至少二维与三维各一例。
- 普通 Step 与自定义循环在相同已接受解上写出，时间坐标、字段与数值一致。
- 两次成功步之间插入一次失败回切：失败试迭代不进入正式时间序列。
- 修改活场后，之前保存帧保持原数值，排除可变对象引用导致所有帧相同。
- 串行和两 rank；跨 rank 写出错误正确传播；相对路径移动目录后仍可读取。
- 科学场成功/展示失败、缺失 H5、损坏引用、空序列、重复坐标、重启动重叠、字段变更都有确定结果。
- 向量补零、插值、积分点恢复均有元数据；不给标量/速度误配 Warp 位移。
- 连续多帧验证不持有全部历史；短程与长程峰值内存分别记录，排除 JIT/后端缓存影响，不提前许诺性能倍率。
- 数值读回以原输出表示的精度为准；发生降阶时另查转换误差，不拿降阶文件与原高阶自由度直接声称无损。
- ParaView 真正打开并完成时间切换和 Warp；记录版本与测试文件，仅对测过的组合声明兼容。

## 7. 本轮不扩张的内容

不开发新文件格式、通用网格转换器或独立 Verify 产品；不新增 VTX/ADIOS2 依赖；不重做 checkpoint；不让输出层管理材料状态提交；不要求所有项目强制双格式；不删除现有专家接口。输出文件读得开，不代替数值验证。

优先把当前串行、MPI 和自定义问题的常用工作流贯通，再依据真实高阶/多网格需求扩展后端。
