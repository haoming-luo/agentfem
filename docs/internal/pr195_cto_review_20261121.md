## Compatibility and usability

- Public function signatures and valid scalar/vector sampling results remain
  unchanged. Sampling, path, section, comparison and gauge operations share
  the same platform-owned point-evaluation path.
- Invalid/reserved input names now fail early with a named diagnostic instead
  of corrupting the response registry or failing only during observation.
  This intentionally tightens admission for those ambiguous experimental
  material declarations; existing noncolliding declarations remain valid.
- Planar `surface_force` retains its existing per-unit-reference-thickness
  input meaning. The factory documentation now explains explicit thickness:
  physical total force is `h0*resultant`; request total `F` with `F/h0` and do
  not also scale `reference_measure`. Load-controlled patches check both
  traction and resultant inputs against force equilibrium and nominal stress.
- No case-owned stiffness, load integration, material Newton, state mutation
  or sampling algorithm was added. Corrections belong in `elements`,
  `mechanics`, `results` and installed API inspection. The standard project
  still uses `model.step(...).solve_result(...)` and `run.publish(...)`.
